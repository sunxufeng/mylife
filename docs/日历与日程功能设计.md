# My Workbench · 日历与日程功能设计

> 版本：v1.2.0 设计稿（待确认）
> 目标：在现有「资料库」之外，补上一条**时间轴**。资料是「事后的记录」，日程是「事前的安排」，
> 两者互相引用，这才是「人生档案馆」完整的形态。

---

## 一、设计目标与边界

**要解决的**：把「什么时候要做什么」也收进 My Workbench，并且能跟已有的资料互相关联与互相印证。

**三条原则**

1. **不引入第二套体系**：日程不是一个独立 App，它就是 My Workbench 的一个新视图 + 一类新记录。
   共用同一套配色主题、同一套交互习惯（右栏内联编辑、软删除进回收站、一键备份覆盖全部数据）。
2. **本地纯离线**：不订阅外部日历、不跟系统日历双向同步。只做「导出 .ics」这一个单向出口。
3. **提醒诚实**：应用没开着就不会提醒。不做后台常驻、不装 LaunchAgent。

## 二、数据模型

### 存哪

放进**同一个 `archive.json`**，新增一个 `schedules` 数组，`ARCHIVE_VERSION` 从 1 升到 2。

```
archive.json
├── version: 2
├── entries: [ … ]        ← 现有资料
├── schedules: [ … ]      ← 新增
├── categories: [ … ]
└── updatedAt
```

**为什么跟资料放一起**：备份 / 恢复 / 旧版迁移 / 损坏兜底这些逻辑一行都不用改，
就自动覆盖了日程。分成两个文件反而要在备份恢复里各写一遍，容易漏。

兼容性：老文件没有 `schedules` 字段 → 归一化成空数组，不报错、不丢数据。

### 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 前缀 `s_`，与资料的 `e_` 区分 |
| `title` | string | 必填 |
| `date` | `YYYY-MM-DD` | 主日期。跨天日程用 `endDate` |
| `endDate` | string \| null | 跨天时才有 |
| `allDay` | boolean | 全天日程，忽略时间 |
| `start` / `end` | `HH:mm` | 时间块；`allDay` 时留空 |
| `location` | string | 地点 |
| `note` | string | 备注，支持 Markdown（复用现有 `markdown.js`） |
| `category` | string | 复用资料现有的分类列表 |
| `color` | string | 6 选 1 色标：绿 / 琥珀 / 蓝 / 珊瑚 / 粉 / 灰；不选则按分类自动分配 |
| `tags` | string[] | 与资料共用标签体系（左栏标签点进去能同时看到资料与日程） |
| `links` | string[] | **关联资料的 id 列表**（多对多） |
| `repeat` | object | `{ freq: 'none'\|'daily'\|'weekly'\|'monthly'\|'yearly', until?: 'YYYY-MM-DD', count?: number }` |
| `remind` | number \| null | 提前多少分钟提醒；`null` = 不提醒 |
| `done` | boolean | 已完成 |
| `createdAt` / `updatedAt` | ISO | |
| `deleted` / `deletedAt` | | 软删除，进回收站 |

### 重复日程怎么处理

**只存规则，不预生成实例。** 渲染月视图时把规则展开成「虚拟实例」，只有当你**单独改某一次**时，
才把那一次拆成独立日程（存 `repeatOf` 指回原始日程）。

好处：改规则只改一条记录；不会因为「重复 3 年」往 JSON 里塞 1000 条。
这也是日历类应用的标准做法。

## 三、界面设计

### 整体：中栏多一种模式

左栏导航新增一项 **「日历」**，排在最上面（日常最常用）。点击后**中栏从列表变成日历**，
右栏语义跟着变。左栏、右栏的收缩行为、配色主题、快捷键体系全部不变。

```
┌──────────┬──────────────────────────┬───────────────────┐
│ My Workbench  │  2026 年 9 月   ‹ ›  月|议程│  9 月 23 日 · 周三 │
│          │  一 二 三 四 五 六 日      │  今天 · 2 条日程    │
│ ▸ 日历   │ ┌──┬──┬──┬──┬──┬──┬──┐   │ ┌───────────────┐ │
│   全部资料│ │  │  │  │  │  │  │  │   │ │10:00–11:30    │ │
│   回收站  │ ├──┼──┼──┼──┼──┼──┼──┤   │ │教学组例会  ○   │ │
│          │ │  │  │●23│ │  │  │  │   │ └───────────────┘ │
│ 分类     │ │  │▬▬│▬▬│ │  │  │  │   │ ┌───────────────┐ │
│  经历    │ ├──┼──┼──┼──┼──┼──┼──┤   │ │15:00–16:00    │ │
│  工作资料 │ │  │  │  │  │  │  │  │   │ │吴倩 1:1 沟通 ○ │ │
│  阅读笔记 │ └──┴──┴──┴──┴──┴──┴──┘   │ └───────────────┘ │
│ ⚙ 设置   │                          │  ＋ 新建日程       │
└──────────┴──────────────────────────┴───────────────────┘
```

### 三个视图

| 视图 | 内容 | 首版 |
| --- | --- | --- |
| **月视图** | 6×7 网格；今天实心圆标记；每格最多显示 2 条日程色条，超出显示「+N」；点击空白格 = 新建，点击日程条 = 选中 | ✅ |
| **议程视图** | 在月视图同一位置按天分组的清单（接下来 7 天 / 30 天可切），适合快速扫一遍「最近要做什么」 | ✅ |
| **周视图** | 7 列 × 时间轴（06:00–23:00），日程按真实时间画成色块 | 待定 |

### 右栏的三种状态（跟资料库一致的心智模型）

| 状态 | 内容 |
| --- | --- |
| 没选中 | **今日概览**：今天的日程时间线、接下来 3 天、本周统计（共几条 / 完成几条 / 有冲突的几天） |
| 选中某天 | 该天日程列表（按时间排序，全天在最上）+ 完成勾选 + 「＋ 新建日程」 |
| 选中某条日程 | 详情：时间、地点、分类、标签、备注（Markdown 渲染）、**关联资料卡片**、重复规则说明、创建 / 修改时间 |
| 编辑中 | 右栏内联表单（见下），不弹模态框 —— 跟资料编辑完全一致的习惯 |

### 交互动手细节

- **新建**：点月视图空白格（自动带上那天的日期）／右栏「＋ 新建日程」／`⌘N`（日历模式下就是新建日程）
- **完成**：日程卡片右侧一个圆圈，点一下切换完成状态（不用进详情）
- **时间冲突**：同一天时间重叠的两条，在右栏给一条浅色提示「与 15:00 的日程重叠」，不阻止保存
- **拖拽改期**（待定）：在月视图里把色条拖到别的日子 = 改日期，拖到「+N」区域也可以
- **键盘**：`←` `→` 切月，`T` 回到今天，`⌘3` 跳到日历视图

## 四、跟现有功能怎么咬合

| 现有能力 | 日程怎么接进去 |
| --- | --- |
| **搜索** | 日历模式下搜索框变成搜日程（标题 / 地点 / 备注 / 标签）；左栏标签点进去同时列资料与日程 |
| **回收站** | 回收站视图分两组显示：资料 / 日程，都能还原或彻底删除 |
| **关联资料** | 日程详情里能看到关联的资料卡片，点开跳到那条资料；**资料详情里反向显示「相关日程」区块** |
| **备份 / 恢复** | 因为存在同一个 `archive.json`，自动包含，代码零改动 |
| **导出 Markdown** | 导出资料时可勾选「附带相关日程」，在对应资料下多一段「相关日程」 |
| **导出 .ics**（待定） | 当前月 / 未来 30 天 / 全部，导出标准 iCalendar 文件，可导进 macOS 日历、Google Calendar |
| **配色主题** | 日程色标是固定 6 色板，与主题强调色错开，换主题不会串色 |

## 五、提醒机制（说清楚能做到什么程度）

- 应用运行期间，主进程每 30 秒检查一次「需要提醒的日程」（含重复展开），到点弹**应用内提示条**
- 左栏「日历」后面挂一个角标 = 今天的日程条数
- 打开应用时如果有「今天还没提醒过」的日程，汇总提示一次
- 可选：走 macOS 通知中心（Electron `Notification`），设置里可关，默认开
- **做不到的**：应用没运行时不会提醒。这是本地离线应用的物理限制，我不会假装能做。

---

## 六、明确不做（首版）

- 不订阅外部日历 / 不与系统日历双向同步
- 不做多人共享、邀请、提醒他人
- 不做附件（日程要放资料就关联一条资料，不重复造附件系统）
- 不做「待办清单」第二种概念 —— 「全天日程」已经覆盖「某天要做的事」
- 不做地点地图、不做视频会议链接

## 八、自测计划

**数据层**（在现有 68 项基础上新增）
- 日程增删改查、软删除进回收站、还原、彻底删除
- 重复规则展开：每周 / 每月（含 31 号这种边界）/ 每年、`until` 与 `count` 上限
- 跨天日程、全天日程的日期范围计算
- 时间冲突检测
- 关联资料：删掉资料后日程里的 `links` 要做清理（不留悬空 id）
- 老版本 archive.json（没有 schedules）能正常读入

**界面端到端**
- 切到日历视图、月视图渲染正确条数与「+N」
- 点空白格新建 → 自动带日期 → 保存后出现在格子与右栏
- 完成勾选、拖拽改期（如果做）
- 选某天时右栏内容正确；选日程时详情正确
- 关联资料后，资料详情里出现「相关日程」
- 回收站里日程与资料分组显示、都能还原
- 备份 → 删几条日程 → 恢复 → 日程条数与内容一致
- 换 5 套主题，日历配色不串

## 九、需要你拍板的 4 件事

1. **周视图**（7 列时间轴）首版要不要一起做？— 我建议**先不做**，月视图 + 议程已经能覆盖日常，
   周视图是「锦上添花但工作量大」的那一类。
2. **拖拽改期**要不要？— 我建议**做**，在月视图里拖着改日期是最自然的手感，成本可控。
3. **系统通知**（macOS 通知中心）要不要？— 我建议**做**，默认开、设置里可关。
4. **.ics 导出**要不要？— 我建议**做**，这是跟系统日历之间唯一有用的出口，格式标准、代码不多。
